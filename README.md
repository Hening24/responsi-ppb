## 📖 Deskripsi Umum & Tujuan Proyek

Proyek ini bertujuan untuk menyediakan layanan backend berbasis RESTful API yang andal dan ringan untuk sistem manajemen sirkulasi peminjaman buku perpustakaan. API ini memungkinkan aplikasi klien (seperti aplikasi mobile Android/iOS, web dashboard, atau sistem perpustakaan digital) untuk:
- Mencatat transaksi peminjaman buku baru oleh anggota perpustakaan.
- Menampilkan seluruh daftar peminjaman beserta statusnya.
- Menyaring data peminjaman berdasarkan status (misal: `Dipinjam`, `Kembali`, `Terlambat`) melalui query parameters.
- Memperbarui status peminjaman dan tanggal pengembalian buku.
- Menghapus riwayat transaksi peminjaman.

## 🗄️ Struktur Data & Schema Database

Tabel utama yang digunakan bernama **`loans`** di Supabase.

### Definisi Kolom:

| Nama Kolom | Tipe Data | Constraint | Deskripsi |
| :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | PRIMARY KEY, IDENTITY | ID unik peminjaman (auto-increment) |
| `member_name` | `VARCHAR(255)` | NOT NULL | Nama lengkap anggota peminjam |
| `member_code` | `VARCHAR(50)` | NULLABLE | Nomor identitas/NIM/Kode anggota |
| `book_title` | `VARCHAR(255)` | NOT NULL | Judul buku yang dipinjam |
| `book_isbn` | `VARCHAR(50)` | NULLABLE | Nomor ISBN atau kode katalog buku |
| `loan_date` | `DATE` | NOT NULL, DEFAULT CURRENT_DATE | Tanggal buku mulai dipinjam |
| `due_date` | `DATE` | NOT NULL | Batas waktu pengembalian buku |
| `return_date` | `DATE` | NULLABLE | Tanggal buku dikembalikan (`null` jika belum dikembalikan) |
| `status` | `VARCHAR(50)` | NOT NULL, DEFAULT 'Dipinjam' | Status peminjaman (`Dipinjam`, `Kembali`, `Terlambat`) |
| `notes` | `TEXT` | NULLABLE | Catatan tambahan / kondisi fisik buku |
| `created_at` | `TIMESTAMPTZ` | DEFAULT NOW() | Waktu pembuatan data transaksi |
| `updated_at` | `TIMESTAMPTZ` | DEFAULT NOW() | Waktu pembaruan terakhir data transaksi |

### Script SQL Migration (Supabase SQL Editor)
Script ini dapat dijalankan langsung di tab **SQL Editor** pada dashboard Supabase:

```sql
-- Buat tabel loans
CREATE TABLE loans (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    member_name VARCHAR(255) NOT NULL,
    member_code VARCHAR(50),
    book_title VARCHAR(255) NOT NULL,
    book_isbn VARCHAR(50),
    loan_date DATE NOT NULL DEFAULT CURRENT_DATE,
    due_date DATE NOT NULL,
    return_date DATE,
    status VARCHAR(50) NOT NULL DEFAULT 'Dipinjam',
    notes TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Constraint status valid
ALTER TABLE loans 
ADD CONSTRAINT check_loan_status 
CHECK (status IN ('Dipinjam', 'Kembali', 'Terlambat'));

-- Aturan Akses RLS (Row Level Security) untuk akses publik anonim
ALTER TABLE loans ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public read access" ON loans FOR SELECT USING (true);
CREATE POLICY "Allow public insert access" ON loans FOR INSERT WITH CHECK (true);
CREATE POLICY "Allow public update access" ON loans FOR UPDATE USING (true) WITH CHECK (true);
CREATE POLICY "Allow public delete access" ON loans FOR DELETE USING (true);
```

## 📡 Dokumentasi Endpoint REST API

### Ringkasan Endpoint

| Method | Endpoint | Deskripsi |
| :--- | :--- | :--- |
| `GET` | `/` | Service info & health check |
| `GET` | `/loans` | Mengambil seluruh data peminjaman buku |
| `GET` | `/loans?status={status}` | Filter peminjaman berdasarkan status (`Dipinjam`, `Kembali`, `Terlambat`) |
| `GET` | `/loans?member_name={nama}` | Filter pencarian berdasarkan nama anggota |
| `GET` | `/loans?book_title={judul}` | Filter pencarian berdasarkan judul buku |
| `GET` | `/loans/:id` | Mengambil detail satu peminjaman berdasarkan ID |
| `POST` | `/loans` | Menambahkan data transaksi peminjaman baru |
| `PUT` | `/loans/:id` | Memperbarui data peminjaman atau status buku |
| `DELETE` | `/loans/:id` | Menghapus data transaksi peminjaman |

## 💻 Panduan Instalasi & Menjalankan Lokal

### 1. Clone Repository
```bash
git clone https://github.com/<username>/<repo-name>.git
cd <repo-name>
```

### 2. Install Dependensi
```bash
npm install
```

### 3. Konfigurasi Environment Variables
Salin template konfigurasi `.env.example` menjadi `.env`:
```bash
cp .env.example .env
```
Buka file `.env` dan masukkan kredensial Supabase Anda:
```env
PORT=3000
SUPABASE_URL=https://xxxxxxxxxxxxxx.supabase.co
SUPABASE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```
> *(Kredensial dapat dilihat pada Supabase: **Project Settings** -> **API** -> **Project URL** dan **Project API Keys / anon key**)*

### 4. Setup Database Supabase
1. Masuk ke dashboard [Supabase](https://supabase.com).
2. Buat proyek baru atau gunakan proyek yang ada.
3. Buka menu **SQL Editor**, buka file `database/schema.sql`, salin seluruh kodenya lalu klik **Run**.

### 5. Jalankan Aplikasi
- **Mode Development (dengan Hot Reload nodemon):**
  ```bash
  npm run dev
  ```
- **Mode Produksi:**
  ```bash
  npm start
  ```
Buka peramban atau Postman lalu akses: `http://localhost:3000/loans`.

## 🚀 Panduan Deployment ke Vercel

Aplikasi ini telah dikonfigurasi dengan `vercel.json` dan folder `api/` sehingga siap di-deploy langsung ke Vercel.

### Cara 1: Menggunakan Web Dashboard Vercel (Paling Mudah)
1. Push repository Anda ke GitHub (pastikan repositori bersifat **Public**).
2. Buka dashboard [Vercel](https://vercel.com) dan login menggunakan akun GitHub Anda.
3. Klik tombol **"Add New..."** -> **"Project"**.
4. Pilih repository GitHub Anda, lalu klik **"Import"**.
5. Pada bagian **Environment Variables**, tambahkan:
   - `SUPABASE_URL` = URL project Supabase Anda
   - `SUPABASE_KEY` = Anon Public API Key Supabase Anda
6. Klik **"Deploy"**.
7. Tunggu hingga proses build selesai. Salin URL hasil deployment (contoh: `https://responsi-ppb-2026.vercel.app`).

### Cara 2: Menggunakan Vercel CLI
```bash
npm install -g vercel
vercel login
vercel
```
Tambahkan environment variables pada Vercel Dashboard setelah project terhubung.
